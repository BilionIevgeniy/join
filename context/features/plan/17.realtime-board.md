# 17. Realtime board

## Why

- JOIN is a team board, but a teammate's change appears only after reload
- Interview angle: "WebSockets in Angular?", "How do you reconcile realtime events with optimistic updates?"

## Scope

1. ADR: Supabase Realtime (Postgres changes vs Broadcast) and how events merge into the stores
2. One channel per current workspace (RLS-respecting Postgres changes on `tasks`, `task_contacts`, `contacts`, `task_files`); subscribe on workspace enter, unsubscribe on leave and sign-out
3. Merge into `TasksStore`/`ContactsStore` with `withEntities`; ignore echoes of own optimistic updates; a conflict (edited while open) shows a notice in the edit dialog
4. Presence (who is online on the board) only if it costs little (decide in the plan)
5. Reconnect handling and a visible "reconnecting" state

## Acceptance criteria

- Two browsers on the same workspace see moves, edits and deletes within a second; a member of another workspace receives nothing (integration test)
