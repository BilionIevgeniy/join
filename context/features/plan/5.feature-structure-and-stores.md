# 5. Feature structure and SignalStores

## Why

- Today the code is split by technical type (`components/`, `pages/`, `core/services/`), with `pages/board` and `components/board` side by side; services both hold state and call Supabase; nothing stops a deep import (e.g. `auth.service.ts` imports `GREETING_INTRO_SESSION_KEY` from `components/summary`)
- German enterprise Angular codebases are organised by feature with enforced boundaries, and most use NgRx
- Interview angle: "How do you structure a large Angular app?", "Smart vs presentational components?", "SignalStore vs services vs classic NgRx?", "How do you enforce module boundaries?"

## Scope (one commit each, behaviour unchanged; the E2E smoke of feature 4 is green after every commit)

1. **Boundary tool first**: install Sheriff (`@softarc/sheriff-core`, `@softarc/eslint-plugin-sheriff`), verify on the installed version the config syntax (`sheriff.config.ts`, tagging, dependency rules) and the ESLint rule names; if it cannot express the rules of `architecture-rules.md`, use `eslint-plugin-boundaries` instead. ADR: feature structure, public `index.ts` per feature, the chosen tool and its verified rule names
2. **ADR: state** — NgRx SignalStore (`@ngrx/signals`, `withEntities`) with `resource()` for loads; the store is the facade (no extra facade layer); rejected with reasons: plain signal services (today), classic NgRx Store, the `@ngrx/signals/events` plugin (plain methods are more predictable at this size), `@ngrx/signals/resource` (experimental), facades on top of stores
   - **Stores keyed by context, no reset methods**: each store's `resource()` takes its context as params (`currentUserId()`, later `currentWorkspaceId()` from 7); a `null` id leaves the resource idle and the store empty, a changed id cancels the in-flight request. No store calls another store's `reset()` (that would break rule 3: `auth → tasks`)
3. **ADR: data contract and mapping** — the generated `Row`/`Insert`/`Update` types of `database.types.ts` are the data contract; domain models are camelCase types in `data-access/*.model.ts`; pure mappers (row ↔ model) live next to the repository and have tests; snake_case and the `Json` type never reach components. Fix the contradiction between "derive with Pick/Omit" (coding standards) and "the repository maps" (architecture rule 7) in the same commit
4. **Dates**: `due_date` is a `date` (no time, no zone); domain functions (`isOverdue(due, today)`, `daysUntil`) take a local `today`; a `CLOCK` `InjectionToken` provides "now" so tests can fix it; display through `Intl`/`DatePipe` with the locale
5. **Move to the target layout** (`context/architecture-rules.md`): `core/`, `shell/`, `shared/ui`, `shared/util`, `features/{auth,contacts,tasks,board,summary,legal}` with `pages/`, `ui/`, `data-access/`, `domain/`, `index.ts`; `git mv` so history follows; path aliases updated; fix the known violations (the greeting key, `pages/board` vs `components/board`)
6. **Repositories**: one `*.repository.ts` per feature holds every Supabase call of today's services (mapping rows to models, typed errors); nothing else imports the client
7. **Stores**: `AuthStore`, `ContactsStore`, `TasksStore` replace the services' state (`withEntities` instead of the hand-written `Record<string, Task>` map; computed counts and columns; optimistic move/toggle with rollback as store methods; loading via `resource()` inside the store); provided where `architecture-rules.md` rule 5 says; `ToastService` and `ModalService` stay plain services in `shared/`/`core/`
8. **Lint the boundaries**: rules 1–4 of `architecture-rules.md` enforced, plus `shell` may import features' `index.ts` and no feature imports `shell`; one deliberate violation proves the rule fails, then reverted
9. **OnPush clean-up**: remove each `ChangeDetectionStrategy.Eager` added in feature 1, one component per commit, checking first the risky ones: `board-column` (`dragCounter` is a plain field), components created by `ModalService` (`createComponent`/`setInput`), `image-viewer` and `modal` (`effect()`); turn plain fields the template reads into signals
10. **Modern APIs everywhere**: `viewChild()` instead of `@ViewChild` (modal), `host: {}` instead of `@HostListener` (header), `inject()` instead of constructor injection, no `standalone: true`, `router.events` subscription in `AuthLayout` with `takeUntilDestroyed`/`toSignal`, `err: any` → `unknown`

## Non-goals

New behaviour, new tests beyond keeping E2E green (6), workspaces (7), Signal Forms (14).

## Acceptance criteria

- The tree matches `architecture-rules.md`; the lint fails on a deep import, on a Supabase import outside a repository and on `shared` importing a feature
- No `Eager`, no decorator APIs the rules replace; E2E smoke green; `npm run lint && npm run typecheck && npm run build` green
