# 19. Hardening: performance, CSP and headers

## Why

- The initial bundle is 547 kB (budget 500 kB) because `viewerjs` (CommonJS) and its CSS load eagerly; `add-task.scss` is over the component budget; no CSP or security headers
- Interview angle: "How do you analyse and reduce bundle size?", "`@defer`?", "What is a CSP and how does it work with Angular?"

## Scope

1. Bundle analysis (`ng build --stats-json` + an analyzer); record before/after numbers in the PR
2. Image viewer and its CSS lazy (`@defer` or dynamic import on first open), or replace `viewerjs` with a small CDK-overlay viewer (decide in the plan)
3. `@defer` for heavy rare UI (task form in dialog, viewer), `NgOptimizedImage`, fonts preloaded and subset
4. Budgets green and tightened to the new numbers
5. Security headers on the host: `Content-Security-Policy` (Angular's `autoCsp` or a hash/nonce strategy compatible with static hosting — verify), `Strict-Transport-Security`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `frame-ancestors`; `connect-src` limited to the Supabase and Sentry hosts of each deploy context (preview → `dev` project, production → `prod` project), written next to `config.json` (2)
6. Check with securityheaders.com / Mozilla Observatory and note the grade

## Acceptance criteria

- No budget warnings; CSP active without console violations; E2E green with the headers on (preview)
