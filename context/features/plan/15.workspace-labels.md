# 15. Workspace labels

## Why

- A task's category is hard-coded (`'User Story' | 'Technical Task'`); every real task tool lets the team define its own labels
- Interview angle: "Many-to-many with RLS", "migrating an enum-like column to a table"

## Scope

1. Migration: `labels(id, workspace_id, name, color)` unique per workspace, `task_labels(task_id, label_id, workspace_id)`; RLS on membership; the two old categories become two labels per workspace, then the `category` column is dropped in a later migration (expand → migrate → contract)
2. Labels page or section in workspace settings (owners and members per the permission matrix of 7): create, rename, recolor (token palette from 10), delete (with confirm)
3. Task form: label picker (the kit's combobox, multi-select); task card and detail show label chips
4. Board filter by label (the filter of 11 switches from category to labels); summary counts by label if useful (decide in the plan)
5. Integration tests: labels of another workspace are invisible and cannot be attached

## Acceptance criteria

- No hard-coded category left; labels are per workspace and filterable
