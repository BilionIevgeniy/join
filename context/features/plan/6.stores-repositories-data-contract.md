# 6. SignalStores, repositories and data contract

## Why

- After the move (5) the services still both hold state and call Supabase, with a hand-written entity map and hand-written rollback; row types and snake_case reach the templates; dates are compared as strings
- Most German enterprise Angular codebases use NgRx; SignalStore is where new code goes
- Interview angle: "SignalStore vs services vs classic NgRx?", "Repository pattern and mapping?", "How do you test time-dependent code?", "OnPush and zoneless?"

## Scope (one commit each; the E2E smoke of feature 4 is green after every commit)

1. **ADR: state** — NgRx SignalStore (`@ngrx/signals`, `withEntities`) with `resource()` for loads; the store is the facade (no extra facade layer); rejected with reasons: plain signal services (today), classic NgRx Store/Effects, the `@ngrx/signals/events` plugin, `@ngrx/signals/resource` (experimental), facades on top of stores (each explained in the handbook)
   - **Stores keyed by context, no reset methods**: each store's `resource()` takes its context as params (`currentUserId()`, later `currentWorkspaceId()` from 8); a `null` id leaves the resource idle and the store empty, a changed id cancels the in-flight request. No store calls another store's `reset()`
2. **ADR: data contract and mapping** — the generated `Row`/`Insert`/`Update` types of `database.types.ts` are the data contract; domain models are camelCase types in `data-access/*.model.ts`; pure mappers (row ↔ model) live next to the repository and have tests; snake_case and the `Json` type never reach components
3. **Dates**: `due_date` is a `date` (no time, no zone); domain functions (`isOverdue(due, today)`, `daysUntil`) take a local `today`; a `CLOCK` `InjectionToken` in `core/time` provides "now" so tests can fix it; display through `Intl`/`DatePipe` with the locale
4. **Repositories**: one `*.repository.ts` per feature holds every Supabase call of today's services (mapping rows to models, typed errors); nothing else imports the client (lint rule from 5)
5. **Stores**: `AuthStore`, `ContactsStore`, `TasksStore` replace the services' state (`withEntities` instead of the hand-written `Record<string, Task>` map; computed counts and columns; optimistic move/toggle with rollback as store methods; loading via `resource()` inside the store); provided where `architecture-rules.md` rule 5 says; `ToastService` and `ModalService` stay plain services in `shared/`
6. **OnPush clean-up**: remove each `ChangeDetectionStrategy.Eager` added in feature 1, one component per commit, checking first the risky ones: `board-column` (`dragCounter` is a plain field), components created by `ModalService` (`createComponent`/`setInput`), `image-viewer` and `modal` (`effect()`); turn plain fields the template reads into signals
7. **Modern APIs everywhere**: `viewChild()` instead of `@ViewChild` (modal), `host: {}` instead of `@HostListener` (header), `inject()` instead of constructor injection, no `standalone: true`, `router.events` subscription in `AuthLayout` with `takeUntilDestroyed`/`toSignal`, `err: any` → `unknown`

## Non-goals

New behaviour, new tests beyond keeping E2E green (7), workspaces (8), Signal Forms (15).

## Acceptance criteria

- Only repositories import the Supabase client; components never see row types
- No `Eager`, no decorator APIs the rules replace; E2E smoke green; `npm run lint && npm run typecheck && npm run build` green

## Tests

The E2E smoke after every commit; mapper and date tests here (pure, cheap); store and component tests in 7.
