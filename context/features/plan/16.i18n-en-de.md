# 16. English and German (i18n)

## Why

- German companies expect German UI support; the app is English-only with texts in templates and services
- Interview angle: "`@angular/localize` vs Transloco/ngx-translate?", "Build-time vs runtime i18n?"

## Scope

1. ADR: library choice — `@angular/localize` (build-time, one build per locale, no runtime switch) vs Transloco (runtime switch, lazy translation files); criteria: runtime switch without reload, static hosting, bundle size, tooling
2. All visible text, toast and error messages (the message maps of 11) as keys; English and German files; dates and numbers via the locale
3. Language switch in the account menu, saved per user (profile) and in the browser; default from the browser language
4. Legal pages stay as written in 13
5. Lint/test that no key is missing in either language; E2E runs in both languages for one journey

## Acceptance criteria

- No hard-coded user-visible text left; switching language changes everything without reload (if the ADR chooses runtime)
