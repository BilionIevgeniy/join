# 11. Routing and UX

## Why

- The task detail is a modal without a URL (no deep link, Back closes nothing, reload loses it); search lives only in a signal; unknown URLs redirect to login instead of a 404; every tab title is "Join"; deletes happen without confirmation
- Interview angle: "Router features you use?", "Component input binding, resolvers, title strategy", "URL as state"

## Scope

1. Task detail and edit as routed dialogs (the kit dialog from 10): `/board/task/:id` and `/board/task/:id/edit` (child routes rendering the modal), `withComponentInputBinding()` for params; Back closes; a missing or foreign id shows a not-found state
2. **Search and filters in query params**: text (debounced), assignee ("Assigned to me"), priority, label (once 15 exists, else category), due (overdue / this week); `/board?q=…&assignee=me&priority=urgent`; shareable, Back/Forward restore them; filter logic as pure functions in `board/domain` with tests
3. A real 404 page; `**` no longer redirects to login
4. Page titles via route `title` and a custom `TitleStrategy` ("Board · JOIN")
5. The kit's confirm dialog before deleting tasks, contacts and members (a delete cascades to assignees and files, so no Undo there); an Undo toast only for moving a task
6. Add task: one route that is a page on mobile and a dialog on desktop, or a documented choice why both stay
7. Preloading strategy for lazy routes (decide in the plan), scroll position restoration

## Acceptance criteria

- Opening a task link in a new tab shows the task; Back/Forward behave; E2E journeys updated
