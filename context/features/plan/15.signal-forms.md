# 15. Signal Forms

## Why

- The forms use Reactive Forms with `toSignal(valueChanges)` bridges; Signal Forms are stable since Angular 22 and the direction of the framework. Most German codebases still use Reactive Forms, so the ADR and the PR must explain both
- Interview angle: "Reactive vs template-driven vs Signal Forms?", "Custom form controls?", "Cross-field and async validation?"

## Scope

1. ADR: Signal Forms for all forms (mixed paradigms rejected); what Reactive Forms knowledge still matters
2. Migrate all forms in one PR, one commit per form: login, sign-up (password match), contact, task form (due date not in the past unless unchanged, required category), invite member, account forms from 9
3. Custom controls: priority buttons, the kit's combobox (assignees, category/labels), subtask editor, file picker as Signal Forms controls (or via the CVA compatibility if the docs recommend it for this case); kit form fields (label, hint, error message) from 11
4. Shared validators in `domain/`; messages in plain words; submit disabled while pending; "unsaved changes" guard (`canDeactivate`) on the task form

## Acceptance criteria

- No `ReactiveFormsModule` left; all form tests from 7 green or rewritten; E2E green
