# 10. Design tokens and shared UI kit

## Why

- `shared/` today holds whatever the course needed (button, avatar, modal, loader, search input, checkbox, priority button); dialogs, menus and dropdowns are hand-made per component, without focus management or keyboard support; colors and spacing are partly hard-coded
- German enterprise teams work with a design system: tokens, one component kit, documented and tested. Angular Material is rejected (its look would replace the JOIN design and fight the custom styles); the kit is built on CDK and `@angular/aria` instead
- Interview angle: "How do you build a component library?", "Design tokens?", "Component harnesses?", "Headless/a11y primitives?"

## Scope (one commit per group)

1. ADR: own kit on CDK + Angular Aria, three token layers; Angular Material rejected with the reason above
2. **Design tokens** as CSS custom properties in `src/styles/tokens/`: primitive (palette, spacing scale, radii, font sizes), semantic (`--color-surface`, `--color-text-muted`, `--color-danger`, focus ring), component (button, input, card); light and dark theme via the semantic layer; Stylelint rule against raw colors outside the token files
3. **Kit components** in `shared/ui/` (presentational, OnPush, `input()`/`output()`/`model()`):
   - button, icon button (required `aria-label`), link button
   - dialog (CDK Dialog: focus trap, Esc, return focus, labelled) and confirm dialog; `ModalService` becomes a thin wrapper or is replaced (decide in the plan)
   - menu (Angular Aria or CDK menu — verify which is stable for this case), combobox/listbox (assignees, category/labels)
   - form field (label, hint, error message slot), text input, textarea, date input, checkbox, priority segmented control
   - toast (live region), skeleton, empty state and error state (presentational: a message input and a `retry` output)
   - avatar, badge/label chip, loader
4. **Harnesses**: a CDK `ComponentHarness` per interactive kit component, used by the kit's own tests and by feature tests (6)
5. Replace the hand-made dialogs, dropdowns and buttons in the features with the kit (behaviour unchanged, E2E green)
6. `docs/ui-kit.md`: each component with its inputs/outputs, states, a11y notes and a usage snippet

## Non-goals

A published npm library, Storybook (rejected in the plan README), the full a11y audit of drag and drop (13).

## Acceptance criteria

- No raw colors outside token files; every dialog, menu and dropdown in the app is a kit component; each kit component has a test using its harness; axe finds no A/AA violation in the kit's states

## Tests

Kit component tests with harnesses (Testing Library for behaviour), plus the existing E2E.
