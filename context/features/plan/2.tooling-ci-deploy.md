# 2. Tooling, CI and deploy

## Why

- No ESLint, no format check, no CI, no branch protection; deploy is a manual FTP upload (`build:filezilla`, `.htaccess`)
- The README describes a NestJS backend that does not exist; 148 generated TypeDoc files (`out/`) are committed
- Interview angle: "What does your CI pipeline check?", "How do you keep code consistent in a team?", "How do previews work?"

## Scope (one commit each)

1. **README rewrite**: what JOIN is, live demo link, stack (Angular + Supabase), scripts, architecture link (`docs/arc42-lite.md`), workflow link (`context/ai-interaction.md`)
2. **Remove TypeDoc**: delete `out/`, `typedoc.json`, the `docs` script and the dependency; add `out/` to `.gitignore`
3. **ESLint**: `ng add angular-eslint` (flat config `eslint.config.js`), recommended TS + template rules, **template accessibility rules**, `no-console` (except tests), size limits from "Size limits" in `coding-standards.md`, a rule against `ChangeDetectionStrategy.Eager` without a disable comment; fix or explicitly disable (with a reason) every finding; `npm run lint`
4. **Prettier**: `format` and `format:check` scripts, `.prettierignore`; one sweep commit, its hash in `.git-blame-ignore-revs`; `.vscode/settings.json` and `extensions.json` (format on save, Angular Language Service, ESLint, Prettier, Stylelint)
5. **Scripts**: `typecheck` (`tsc -p tsconfig.app.json --noEmit` and the spec config), `lint:dup` (jscpd report, not a gate)
6. **Environments**: `environment.ts` (dev) and `environment.prod.ts` with `fileReplacements`; `.env.example` documents what CI/hosting needs
7. **Commit hygiene**: husky + lint-staged (Prettier and ESLint on staged files) + commitlint (conventional commits)
8. **CI** `.github/workflows/ci.yml`, job `ci` on PR and push to `main`: `npm ci`, `format:check`, `lint`, `lint:styles`, `typecheck`, `test`, `build`; npm cache; concurrency cancels old PR runs; `permissions: contents: read`
9. **Deploy**: choose the static host in the plan (candidates: Netlify, Cloudflare Pages, Vercel — EU data location and free PR previews decide; record it in an ADR), SPA fallback, deploy of `main` to production and of each PR to a preview URL; remove `build:filezilla` and `public/.htaccess`
10. **Branch protection** on `main`: PR required, `ci` required, no force push
11. **Optional SonarQube Cloud** (free for public repos): analysis from CI, not automatic analysis; its quality gate becomes required only in feature 6, when coverage exists

## Non-goals

Module boundaries in the lint (5), tests (4, 6), CSP and headers (15).

## Acceptance criteria

- `npm run format:check && npm run lint && npm run typecheck && npm run test && npm run build` green locally and in CI
- A PR shows the `ci` check and a preview URL; a merge to `main` deploys production
- README matches the code
