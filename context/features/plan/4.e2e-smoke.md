# 4. E2E smoke tests

## Why

- Feature 5 moves every file and changes every import; `strictTemplates` catches broken imports, but only a browser test catches changed behaviour
- Interview angle: "How do you refactor safely?", "Playwright vs Cypress?"

## Scope

1. Playwright (`@playwright/test`), `playwright.config.ts`: Chromium (plus a mobile viewport project), `webServer` builds and serves the app against the local Supabase (`npm run db:start` + seed); traces on failure
2. Test data: each test signs up its own user or uses the demo, so tests do not depend on each other; helpers in `e2e/support/`
3. Journeys (stable selectors: roles and labels first, `data-testid` only where no accessible name exists):
   - sign up, sign out, sign in
   - demo (anonymous) sign-in reaches the summary
   - create a task with an assignee and a subtask, see it on the board, move it to another column, toggle the subtask, delete it
   - contact create, edit, delete
4. `npm run test:e2e`; CI job `e2e` (supabase start, seed, build, Playwright), the report as an artifact on failure; required check once green

## Non-goals

Full coverage of every page (23), visual regression.

## Acceptance criteria

- The four journeys pass locally and in CI; `e2e` is required
