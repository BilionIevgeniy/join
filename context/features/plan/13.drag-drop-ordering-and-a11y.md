# 13. CDK drag and drop, ordering and accessibility

## Why

- Tasks have no order inside a column; native HTML5 drag and drop does not work on touch; clickable `<div>`s and custom dropdowns lack keyboard handling; the modal has no focus trap; the BFSG (in force since 2025-06-28) makes WCAG 2.1 AA the expectation in Germany
- Interview angle: "How do you make drag and drop accessible?", "What is BFSG?", "How do you test accessibility?"

## Scope

1. **Ordering**: `tasks.position` with fractional keys (a text or numeric key between neighbours, so a move writes one row); migration fills positions from `created_at`; RPC `move_task(id, status, after_id, before_id)` is the single write (checks membership and `version` from 7); ADR
2. `@angular/cdk/drag-drop`: connected lists for the columns (`cdkDropListGroup`, `cdkDropList`, `cdkDrag`), reordering inside and across columns, preview and placeholder styles; the store's optimistic `moveTask` calls the RPC and rolls back on error
3. Keyboard alternative: the kit's "move to" menu on every card (column and position: top / bottom / before / after), announced in a live region
4. Assignee and category pickers use the kit's combobox (10); the remaining custom dropdowns are replaced by kit components
5. Visible focus styles; contrast check of the theme tokens (10)
6. axe checks: `@axe-core/playwright` in the E2E journeys (no violations of level A/AA), plus the template lint rules from 2
7. Accessibility statement page (Barrierefreiheitserklärung) in `legal`, with the known limitations and a contact

## Acceptance criteria

- Order inside a column survives a reload and is the same for every member; the whole app works with keyboard only; drag and drop works on a phone; axe reports no A/AA violations on the main pages
