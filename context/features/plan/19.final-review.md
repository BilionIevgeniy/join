# 19. Final review pass

## Why

- Before the handbook is written from the code, the code should be the version the author wants to explain

## Scope

1. `security-auditor` full audit; fix findings
2. `code-reviewer` over all of `src/`; `/cleanup run`; `npm run lint:dup`
3. Docs check: README, `docs/arc42-lite.md`, ADRs, `context/` match the code; screenshots and a short demo GIF in the README
4. Lighthouse (performance, accessibility, best practices) on the production URL; numbers in the README
5. Tag `v1.0.0`, release notes from `context/feature-history.md`

## Acceptance criteria

- No open Critical/High findings; docs match the code; `v1.0.0` released

## Model

- Plan: sonnet
- Implementation: sonnet
- architecture-reviewer: opus
