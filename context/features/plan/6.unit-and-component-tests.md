# 6. Unit and component tests

## Why

- Vitest is configured but there are 0 tests; `angular.json` still has `skipTests: true` for new components
- Interview angle: "What do you unit-test in Angular and how?", "TestBed vs Testing Library?", "How do you test signals, stores and guards?", "Testing zoneless apps"

## Scope

1. Setup: remove `skipTests: true`; `@testing-library/angular` + `@testing-library/user-event`; Vitest coverage (v8) with a threshold for `features/*/data-access`, `features/*/domain`, `shared/util` (start at what the tests reach, at least 80 % lines there); `test:ci` script with coverage
2. Pure functions: `shared/util/*`, `features/*/domain/*` (validation, deadline, grouping, initials/color)
3. Repositories: mapping and error mapping with a fake Supabase client (a small typed fake, no network)
4. Stores (TestBed, fake repository): load success and error, computed columns and counts, optimistic move and subtask toggle **with rollback**, sign-out clears state
5. Guards: `authGuard`/`guestGuard` (redirect `UrlTree`s) via `TestBed.runInInjectionContext`
6. Components (Testing Library): task form (validation messages, disabled submit while pending, emitted value), task card (priority, progress, assignees "+N"), board column (empty state, add button), login (error message kept with input), toast container (live region)
7. `ModalService`: open/close lifecycle, inputs and outputs wired, scroll lock released
8. CI: coverage report as artifact; the SonarQube Cloud gate (if set up in 2) becomes required

## Non-goals

Tests against Supabase (integration, from 3) and in the browser (4, 18); 100 % coverage.

## Acceptance criteria

- Coverage threshold met and enforced in CI; tests read as documentation of the rules
