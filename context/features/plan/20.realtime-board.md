# 20. Realtime board

## Why

- JOIN is a team board, but a teammate's change appears only after reload
- Interview angle: "WebSockets in Angular?", "How do you reconcile realtime events with optimistic updates?"

## Scope

1. ADR: Supabase Realtime (Postgres changes vs Broadcast) and how events merge into the stores: the channel callback calls a store method `applyRemoteChange` (no events plugin, no feature flag — both are handbook topics)
2. One channel per current workspace (RLS-respecting Postgres changes on `tasks`, `subtasks`, `task_contacts`, `contacts`, `task_files`, `task_comments`); subscribe on workspace enter, unsubscribe on leave and sign-out
3. Merge into the stores with `withEntities`; ignore echoes of own optimistic updates (by `version`); a newer `version` of the task open in the edit dialog shows a notice with "reload" (the save would fail with `conflict` from 8 anyway); new comments appear in the open task detail
4. Reconnect handling and a visible "reconnecting" state

## Acceptance criteria

- Two browsers on the same workspace see moves, edits and deletes within a second; a member of another workspace receives nothing (integration test)
