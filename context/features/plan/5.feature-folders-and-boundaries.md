# 5. Feature folders and boundary lint

## Why

- Today the code is split by technical type (`components/`, `pages/`, `core/services/`), with `pages/board` and `components/board` side by side; nothing stops a deep import (`auth.service.ts` imports `GREETING_INTRO_SESSION_KEY` from `components/summary`)
- The public pages (privacy, legal notice, help) live inside `MainLayout`, whose start-up loads all contacts and tasks: a signed-out visitor opening `/privacy` triggers data requests
- Interview angle: "How do you structure an Angular app by feature?", "Smart vs presentational components?", "How do you enforce boundaries without a monorepo?", "Why not Nx here?"

## Scope (behaviour unchanged; the E2E smoke of feature 4 is green after every commit)

1. **ADR: feature folders with a public `index.ts` per feature and Sheriff for the boundaries** — options: today's type folders, feature folders + Sheriff, an Nx monorepo with libraries; Nx rejected for one app, one team and one deployable (Nx pays off with several apps or teams); verify Sheriff's flat-config package and rule names on the installed version first, fallback `eslint-plugin-boundaries`
2. **Move to the target layout** of `context/architecture-rules.md` (`core/`, `shell/`, `shared/ui`, `shared/util`, `features/*` with `pages/`, `ui/`, `data-access/`, `domain/`, `index.ts`), one feature per commit with `git mv` so history follows; today's services move into the features' `data-access/` as they are (stores and repositories come in 6); path aliases updated; fix the known violations (the greeting key, `pages/board` vs `components/board`)
3. **`PublicLayout`** in `shell/` for login, sign-up, privacy, legal notice and help: no data loads, no sidebar for signed-out visitors; `MainLayout` only for signed-in routes
4. **Lint the boundaries** (Sheriff tags per folder): rules 1–4 of `architecture-rules.md` — only repositories/`core/supabase` import the client, imports between features only through `index.ts`, the dependency direction, `shared`/`core` never import features, `shell` may import features' `index.ts`; one deliberate violation per rule proves the lint fails, then reverted

## Non-goals

SignalStores, repositories, mappers (6); new tests beyond keeping E2E green (7).

## Acceptance criteria

- The tree matches `architecture-rules.md`; the lint fails on a deep import, on a wrong dependency direction and on `shared` importing a feature
- Opening `/privacy` signed out sends no request for tasks or contacts (E2E)
